# AGENTS.md

Mapgen4 is a browser-based procedural map generator (Red Blob Games). Written in TypeScript/Vanilla JS + Web Workers + WebGL2 (no framework until the original `regl` was removed). ESM only.

## Build / run

- Build: `./build.sh`. Requires `esbuild` on PATH (README says `npm install -g esbuild`; it is also in `dependencies`, so `npm install` puts it in `node_modules/.bin`).
- Dev: serve the repo root, e.g. `python3 -m http.server 8000`, then open `embed.html` (not `index.html`; there is none — it's gitignored).
- Deploy: push to `main` triggers `.github/workflows/pages.yml` which runs `./build.sh` and deploys `embed.html` + `build/` to GitHub Pages. CI installs esbuild globally.

There is **no lint, no typecheck, and no test command**. esbuild does not type-check, and `typescript` is not installed anywhere, so "typechecking" is IDE-only (per README). Verify changes by building and opening the page in a browser. Type declarations (`.d.ts`) exist for the IDE.

## Build artifacts

- `build/` is fully gitignored and regenerated by `./build.sh`:
  - `_bundle.js` — main app (entry `mapgen4.ts`, loaded by `embed.html`)
  - `_worker.js` — map-generation Web Worker (entry `worker.ts`), built separately
  - `points-<spacing>.data` — precomputed points for the legacy single-mesh path (`mesh.ts`, `generate-points-file.ts`). **The app no longer uses this at runtime**: tiles are generated in the worker from `world`/`lod` config, so this file is now a build-time artifact only.

## Conventions to preserve

- **Explicit `.ts` extensions on relative imports** everywhere (`./map.ts`, `./dual-mesh/index.ts`). TS libs/dual-mesh authored under `tsconfig.json` with `allowImportingTsExtensions`. Don't strip or add them inconsistently.
- **Modify `config.js` (not hardcoded values)**: `world.size` (default 4000; 4×4 = 16× the original area) and `lod.*` control the tile pyramid. `world.baseSpacing` (5.5) is the native detail scale = `config.spacing`. `mesh.seed` drives the world-level mountain peaks in the worker.
- Every source file starts with an Apache-2.0 Red Blob Games header comment; keep it on new files.
- `param` object — UI sliders are declared in `mapgen4.ts`'s `initialParams` and merged into `config.js` sections at runtime.

## Code map

- `mapgen4.ts` — entrypoint/UI wiring; creates the `WorldManager` + `Renderer`, talks to the worker (init + per-tile genTile messages).
- `world.ts` — `WorldManager`: quadtree tile pyramid, LOD selection from zoom, viewport culling, LRU tile cache, painting invalidation. Every tile at every LOD holds ~same cell count (native detail scale), so detail is consistent and visible cells stay bounded.
- `tile-mesh.ts` — builds one tile's `TriangleMesh` in the worker (Delaunator + ghost structure + shared mountain peaks).
- `mesh-extras.ts` — serialize/deserialize `TriangleMesh` across the worker boundary + `addMeshExtras` (is_boundary_t, length_s).
- `worker.ts` — map generation in the worker; per-tile `genTile` messages; caches tile meshes and per-scene `Map` instances; scales `lg_min_flow` per LOD (river continuity).
- `map.ts` — terrain algorithms (elevation, rainfall, rivers); now world-size-parameterized.
- `painting.ts` — user brush painting → constraints.
- `render.ts` — WebGL2 renderer; screen-space adaptive pipeline (renders only visible tiles per frame into 2048² framebuffers), per-tile GPU buffers, viewport culling, LOD fallback.
- `generate-points.ts` / `serialize-points.ts` — point precomputation (legacy) + per-tile/peak helpers (`chooseTilePoints`, `generateMountainPeaks`).
- `geometry.ts` — shared worker+render geometry math; fills the QuadGeometry buffers.
- `benchmark.ts` — FPS/render/gen/cells/memory collector (config `benchmark.enabled`).
- `dual-mesh/` — vendored subrepo (see `git subrepo pull dual-mesh` history), the Delaunay+Voronoi dual mesh library. Root build imports `dual-mesh/index.ts` directly (not its `dist/`); its `dist/` is committed and rebuilt only via `npm run dist` (`tsc`) inside that subpackage. Don't edit `dual-mesh/dist/` by hand.

## Gotchas

- Native ES modules + Web Workers: no module bundling assumptions in the browser beyond what esbuild emits.
- Seeds produce deterministic maps; `param.elevation.seed` etc. are the knobs shown in the UI.
- `worker.ts` registers its handler as `globalThis.onmessage = ...` so the same module can be bundled and smoke-tested under Node (mock `self`).
- In `worker.ts`, `Map` is imported as `MapGen` because the built-in `Map` is also used for caches.
- Per-tile overlay arrays (border/road/building/tree/canopy) are allocated lazily and scene-aware to bound memory; `world.maxTiles` (24) caps the LRU cache. Each tile costs ~30k cells regardless of LOD.
- Parallel generation: `world.maxWorkers` (4) workers handle genTile round-robin; `lod.maxInflight` (12) caps tiles in flight. The worker thread never rebuilds a tile's mesh on regen (cached by meshKey) — only the `Map` reassigns.
- Painting regenerates in **serialized rounds** while the brush moves (one round in flight at a time; `lod.paintDebounceMs` = delay before a round fires), so the real terrain follows the brush like the original mapgen4. An optional live colored brush overlay (`Painting.preview` soft discs drawn in `render.ts` `drawPreviews`) exists but is off by default (`lod.paintPreview`).
- The renderer is demand-driven: it renders only when `updateView()` is called (sliders, tile-ready, painting). Enable continuous rendering for FPS benchmarks via `benchmark.enabled` in `config.js`.
